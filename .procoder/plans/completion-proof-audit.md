### P0 — repository tests execute with gates-service authority

**Defect; parent security/gates ownership.** `cmd/gates/main.go:126` composes `gates.NewController`; `internal/gates/wiring.go:134-169` materializes tenant source in the gates container and installs `analysis.DefaultExec`; `internal/analysis/analysis.go:37-47` launches `exec.CommandContext` with inherited environment. `analysis.Tests` executes repository `go test` code. Required leaf: run every repository-controlled dynamic check in an isolated, immutable analysis job with no control-plane environment, mounts, service-account token or unrelated tenant access. Prove with a malicious-but-owned test fixture that service credentials and sibling data are inaccessible, while real gates still return exact revision-bound evidence. Do not solve this with string scanning, a success adapter, or trusting `go test` as a safe binary name. Audit other analysis subprocesses and compiler/build hooks under the same boundary.

`internal/gitops/http.go:144-177,236-246` buffers complete request and response; SSH push reads the complete pack at `ssh.go:242`, while output is also mirrored into a buffer (`269-281`). This is a production memory failure path, not merely a missing benchmark. Parse only bounded ref-command framing before streaming/spooling the pack; retain exact authorization and status parsing. Demonstrate large binary clone/fetch/push, cancellation, multi-ref partial rejection, concurrent clone/push and disk exhaustion with bounded RSS.

## Architecture

Git mutations publish Redis events consumed by CI and indexing; CI dispatches outbound-connected runners or Agent Runs. Runtime must obtain Work-owner frozen intent and capability-owner authority before provisioning, then persist completion and prove termination/revocation before release. Engineering Runs combine actual runtime provenance, independent current-head reviews and deterministic gates before the Git owner performs a guarded merge. Graph receives revision-bound evidence from real producers; context and maintenance read through owner APIs. Deployment and credential actions require separate durable pre-issuance journals and exact cleanup fences. The failure class is consistently the seam: components are reviewed, but the production caller, configuration, security boundary or durable evidence path is absent.
